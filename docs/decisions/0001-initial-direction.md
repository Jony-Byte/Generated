# ADR 0001 — 日次対話とMarkdownから始める

日付: 2026-10-04 JST / 決定者: Jony / 状態: 採用、実装予定

## 背景

GeneratedはAIが管理するニュースサイト。ユーザーが毎日1回プロンプトを送る。既存のNext.jsアプリにETB部品があり、記事・DB・公開設定は今回未確認または未実装。

## 決定

1. Next.jsを継続する。
2. 記事は通常のMarkdownと構造化メタデータでGit管理する。
3. 調査・制作は日次対話から実行し、公開時に確定した記事を配信する。
4. 開発・運営の状態をSTATUS、BACKLOG、日付付きログに残す。
5. 技術・科学・インターネットから始める。AIの立場、出典、訂正を表示する。
6. ETB部品は必要なものだけ整理して使う。

## 代替案と見送る理由

- フレームワーク移行: 静的ニュース配信に適した選択肢はあるが、既存基盤を捨てる利益が今は小さい。
- 初日からDBと管理画面: 日次の単独編集には管理負担が先に増える。
- 初日から定期API実行: 編集・検証・復旧の基準を評価する前に無人化することになる。
- 全文MDX: 記事に任意コードは不要。
- ETB部品の全面採用: ゲーム・フォーム向けの挙動とニュース閲覧の必要性が一致しない。

## 利点と代償

差分が読みやすく、毎日の再開が容易。外部接続がなくても開発と原稿準備ができる。
一方、公開には再ビルドが必要で、同時編集や多数の記事の横断検索には限界がある。Git履歴だけでは読者への訂正表示にならないため、変更履歴を記事データとしても持つ。

## 見直す条件

再ビルドが運営を妨げる、同時編集が必要、検索が遅い、日次運営が安定してAPI自動化の利益が明確になった場合。変更時は後継ADRを作り、記事IDと公開URLを維持する。

根拠: [リサーチ](../RESEARCH.md)、詳細: [技術設計](../ARCHITECTURE.md)。

## 後続の判断

[ADR 0002](0002-living-articles.md)で、記事を育てる体験と共通の根拠パッケージを追加した。Next.js・Markdown・日次対話という基盤は維持する。根拠データの格納と派生文章・質問機能の扱いは後続設計を適用する。

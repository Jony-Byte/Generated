# Generated — サイト設計

更新日: 2026-10-04 JST / 管理: Jony / 状態: 初期設計を採用、実装は未着手

## 1. 作るもの

**世界の技術と科学の動きを、日本語で理解できる、出典をたどれるニュースサイト。**

読者は、新しい技術・インターネット・科学に関心があるが、毎日複数の英語サイトを読み比べる時間はない人。移動中に見出しを確認し、気になる記事を数分で読み、必要なら原典へ進めることを目指す。

Generatedの文字ロゴを中心に据え、AIが編集することを隠さない。文章は落ち着いた「です・ます」調。GIGAZINEを参考に、具体的な出来事から入り、仕組みと背景まで説明する。画面は記事を主役にし、大きな宣伝文句や常時動く装飾は置かない。

### ユーザーが決めたこと

- 名称はGenerated。
- AIが全面的に管理するニュースサイトを作る。
- ハルシネーションの可能性を伝える。
- 文体はGIGAZINE寄り。
- 設計ファイルはJonyが管理してよい。
- ETBの部品は利用・変更・削除のいずれも可能。
- ユーザーが毎日1回、プロジェクトを進めるプロンプトを送る。

### Jonyが選んだ初期方針

- 日本語、技術・科学・インターネット文化を中心に開始する。
- 1回の運営で新規記事0〜3本を目安にする。本数のためには書かない。
- 読みやすさ、出典、訂正を優先し、初期は広告・アカウント・コメントを設けない。
- 記事はMarkdownで管理し、既存のNext.jsから配信する。
- APIによる無人の定期実行は後の段階。まず日次の対話から実行できる編集部を作る。

これらは調査から導いた設計判断であり、過去に指定された要件ではない。変更時は判断記録を追加する。

## 2. 読者に届ける価値

1. **何が起きたかがすぐ分かる。** 見出し、短い導入、必要な場合の要点3つ。
2. **背景まで理解できる。** 既存の仕組みとの違い、日本での利用可否、研究の限界を補う。
3. **根拠を確認できる。** 本文のリンクと末尾の出典一覧を用意する。
4. **変化や誤りを追える。** 初回公開と更新を区別し、重大な訂正は本文の上でも知らせる。

他社記事の翻訳だけで終わらず、原典確認、資料の照合、用語説明などで読者の理解を増やす。大量生成自体を成果にしない。根拠は[リサーチ](RESEARCH.md)、実行規則は[編集方針](EDITORIAL.md)に記載する。

## 3. 扱うテーマ

| カテゴリ | 初期の対象 | 注意点 |
| --- | --- | --- |
| テクノロジー | AI、ソフトウェア、ウェブ、ハードウェア | 提供開始・予告・試験提供を区別 |
| サイエンス | 宇宙、基礎研究、環境、新しい技術 | 論文の条件と限界を説明 |
| インターネット | デジタル文化、オープンソース、サービス | SNSの噂を事実に変換しない |

AI、セキュリティ、宇宙などはタグにする。記事が少ない時点ではカテゴリを細分化しない。医療・投資・紛争・選挙・個人への重大な告発は初期の日常運営の中心に置かず、扱う場合は編集方針の追加確認を通す。

## 4. ページと読み方

| URL案 | 内容 | 優先度 |
| --- | --- | --- |
| `/` | 注目記事、最新記事、最終記事公開日時 | 最初 |
| `/articles/[slug]` | 本文、出典、AI表示、公開・更新日時、訂正 | 最初 |
| `/about` | GeneratedとJony、AI運営、運営主体・連絡先 | 最初 |
| `/editorial-policy` | 読者向け編集方針 | 最初 |
| `/corrections` | 訂正・撤回の一覧 | 最初 |
| `/category/[slug]` | カテゴリ別一覧、ページ送り | MVP |
| `/archive/[year]/[month]` | 月別アーカイブ | MVP |
| `/feed.xml` | 公開記事のRSS | MVP |
| `/search` | 見出し・概要・タグの検索 | 記事が増えてから |
| `/topics/[slug]` | 継続テーマの経緯と関連記事 | 後日 |

### トップページ

ヘッダーはGeneratedの文字ロゴ、カテゴリ、運営方針へのリンク。直下に「AIが選び、調べ、書くニュース。誤りが含まれる可能性があります。」を短く表示する。

上部に注目記事1本と補助の記事2本までを配置し、その下を公開日時順の一覧にする。注目枠と一覧で同じ記事を重複表示しない。公開記事が少なければ通常の一覧だけにする。順位は読者への影響、新規性、根拠の強さ、テーマの偏りを考えてJonyが選び、理由を作業ログに残す。

一覧にはカテゴリ、見出し、短い概要、公開時刻、画像がある場合だけサムネイルを置く。訂正は文字のラベルでも知らせる。無限スクロールは使わず、1ページ20件を目安に前後移動できるようにする。

### 記事ページ

1. カテゴリ、見出し、導入。
2. 「Generated編集部 / Jony（AI）」、初回公開、更新日時。
3. 短いAI表示。重大な訂正・撤回があれば目立つ告知。
4. 権利を確認できた画像または自作図。画像なしでも成立させる。
5. 本文。長い記事だけ目次や要点を付ける。
6. 出典のタイトル・発行元・日付・リンク、確認できない点。
7. 更新・訂正履歴、関連記事、誤りの報告先。

「AIの確信度93%」のような数字は出さない。出典数だけでも品質を表現しない。「公式発表を確認」など、実際に行った確認を記述する。

### 空・失敗・撤回の状態

記事0件では準備中と表示し、架空のニュースを埋めない。検索0件では条件を変える手段を示す。画像が欠けても本文を読める。訂正一覧が空なら「公開済みの訂正はまだありません」とする。取得失敗と記事0件を区別する。撤回は元URLに理由を残し、通常のおすすめから外す。

## 5. 見た目の方向

以下は参考サイトの実測値ではなく、Generated向けの初期案。

| 要素 | 初期案 |
| --- | --- |
| 背景 / 文字 | 暖かい白 `#FAFAF7` / 濃い黒 `#171717` |
| 補助文字 / 線 | `#595959` / `#DADAD4` |
| アクセント | 深い青 `#174EA6`。リンク、選択状態に限定 |
| 本文 | 日本語のシステムフォント、18px前後、行高1.85 |
| 記事の幅 | 720px前後。狭い画面では左右20px程度の余白 |
| サイト全体 | 最大1200px前後。モバイルでは1列 |
| 見出し | 記事見出し28〜44px、太字。極端な長文は編集する |
| 装飾 | 細い区切り線、控えめな角丸 |
| 動き | 操作に必要な変化に限定。動きを減らす設定に対応 |

日本語本文に大量のWebフォントを追加しない。Geistは既存の英字ロゴや補助表記に使うか、実装時に判断する。ダークモードはライト版の読書体験が整った後に実装する。

通常文字のコントラスト4.5:1以上を確認し、主要操作の領域は44px程度を目標にする。24pxのWCAG最小基準と44pxの設計目標を混同しない。キーボード操作、フォーカス表示、200%拡大、320px幅も確認する。[W3C: コントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[操作対象の大きさ](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## 6. ETB部品の使い方

`Icon` は再利用候補。`Button`・`Input` はニュース向けに整理してから利用する。`Shell` はフォーム寄りの幅と大きな下余白があるため、ニュース用レイアウトを別に作る。`Morph`・`MorphDialog`・`Picker` は初期には保留する。

部品を残すために機能を作らない。採用時にゲーム固有の挙動、専用トークン、アクセシビリティ、Client Component境界を点検する。今回の設計作業では部品自体は変更していない。

## 7. 実装順と完成の条件

記事の形式と公開対象の判定 → 記事ページと一覧 → 出典・訂正・AI表示 → RSS・メタデータ → 公開と復旧の順に作る。[作業一覧](BACKLOG.md)を受け入れ条件の正本とする。

MVPは、根拠付きの実在ニュースを3本以上読め、出典へ進め、訂正でき、スマートフォンでも読める状態。記事数はリリース時の表示確認用の目安であり、不適切な記事を出す理由にしない。

性能目標は実利用の75パーセンタイルでLCP 2.5秒以内、INP 200ms以内、CLS 0.1以下。公開前のラボ測定と実利用データは区別する。[web.dev](https://web.dev/articles/vitals)
